# ローカルコーディングエージェントとしてのファイル処理

Kiloの目的は、ローカルLLMをClaude CodeやCodexと同様に使うことである。既存の
office_*.pyは便利な補助・実装例であり、そこに定義済みのコマンドが能力の上限ではない。

## 役割分担

- plan(qwen3.8): 要件を整理し、必要なら既存の読み取り専用コマンドで実ファイルを調査して、
  実装手順・対象・確認方法を決める。ファイルは変更しない。
- code/debug(qwen3.8): 計画を受け、コード作成・実行・成果物の再読込検証まで完遂する。

## Office文書・データ加工の実行手順

Excelの表からコメント・所見・評価文を生成して同じブックへ記入する依頼には、以下の
汎用手順を使わず、codeエージェントから専用の定型経路を使う。外部絶対パスなら
`excel_import`、続けて `excel_comment` を実行する。input/またはwork/内なら
`excel_comment` を直ちに実行する。対象シートを個別指定せず、表示中のコメント対象
シートを必ずすべて一括処理する。エージェントの切替を利用者へ求めず、独自Pythonを
作らず、専用ツールが返す実データ抽出・生成・書込み・output保存・再読込検証まで完了する。

1. input/ の対象ファイルを実際に読み、シート・段落・表・書式など必要な構造を確認する。
   ユーザーが@メンションまたは絶対パスで外部ファイルを明示した場合は、その指定を
   読み取り承認とみなし、次のコマンドでwork/imports/へ作業コピーを作る。
   `text-processing-bridge\.venv\Scripts\python.exe tools\safe_file_import.py "外部ファイルの絶対パス"`
   以後は外部原本ではなく、表示されたwork/imports/のコピーだけを使用する。
2. ユーザーの条件を論理式に言い換える。曖昧さが結果を変える場合だけ質問する。
3. 既存コマンドで完了できなければ、依頼専用のPythonを work/ に直接作る。
   恒久的な個別ツールをtools/へ追加しない。
4. 次の形で安全ランナーから実行する。
   `text-processing-bridge\.venv\Scripts\python.exe tools\safe_task_runner.py work\task.py`
5. 元のinput/は保存先にしない。成果物は必ずoutput/へ分かる名前で保存する。
6. 成果物をライブラリで再度開き、要求した変更、シート数・表数、主要文字列などを検証する。
7. 実行した内容、成果物のパス、書式・マクロ等の制約があれば簡潔に報告する。

## Office文書を人間と同じまとまりで読む

OfficeファイルはLLMが直接見るのではなく、読み取りコマンドやライブラリの出力を介して読む。
ツール呼び出し自体は正常であり必須である。ただし、ツールの既定出力は文書の一部分を
直列化した観察結果にすぎず、画面上の配置・所属関係・省略された内容を完全には表さない。
ツール出力に無いという理由だけで「該当内容は無い」と結論してはいけない。

文書を調べるときは、次の順序を守る。

1. 全体を一覧し、シート、ページ相当の区切り、見出し、表、使用範囲を把握する。
2. ユーザーが示した語句をアンカーとして実セル・段落・表セルを検索する。
3. 一致箇所だけを答えず、その前後・上下左右・同じ枠や同じ節に属する内容を追加取得する。
4. 結合、罫線、インデント、見出しレベル、空行、改ページなどから人間が見る論理的な
   まとまりを復元し、「見出し」「本文」「注記」「出典」等の関係を確認する。
5. 抽出結果とファイル構造を別の方法でも照合する。取得漏れの可能性が残る場合は
   「無い」ではなく「現在の抽出では確認できない」と区別し、追加調査する。

### Excel

- `pandas.read_excel()`、`DataFrame.head()`、端末表示だけでシート全体を読んだと判断しない。
  先頭行数や表示列が省略されるため、対象語を全セルから検索してセル座標を特定する。
- タイトルセルを見つけても、そのセルだけを表とみなさない。下・右のセル、結合範囲、
  外周罫線、空白行、次の見出しまでを調べ、同じ視覚的な枠に入る本文と注記を取得する。
- 結合セルは値が左上セルだけに保存されることを前提に、`merged_cells.ranges` と照合する。
- `MergedCell object attribute 'value' is read-only` はアクセス権や環境制約ではない。指定座標が
  結合範囲内の左上以外だったことを示すため、該当する `merged_cells.ranges` の
  `min_row, min_col` に書込先を変更して再実行する。コメント等の複数行本文は行ごとに
  隣接セルへ分割せず、本文領域の左上セルへ改行を含む1文字列として書く。
- 生成済み本文をセルへ入れるだけなら、次の結合セル対応コマンドを優先して使う。
  `text-processing-bridge\\.venv\\Scripts\\python.exe tools\\office_excel.py set INPUT --sheet SHEET --cell CELL --value-file output\\本文.txt`
  `CELL` は見出しではなく本文領域を指定し、実行後は出力ファイルを再度開いて値を照合する。
- 非表示行列、折り返し、行高・列幅、数式、コメント/メモ、ハイパーリンクも依頼との関連が
  あれば確認する。数式の確認では必要に応じて `data_only=False` と `True` の両方を使う。
- グラフ、図形、テキストボックス等は通常のセル走査では読めない。存在を確認したら
  OOXMLまたは別の適切な方法で調べ、セルに無いことを内容不存在と誤認しない。
- 既存の `excel_reader.py` や `office_excel.py show` で範囲が足りなければ、対象ファイル専用の
  読み取りコードを `work/` に作り、`safe_task_runner.py` 経由で実行する。

### Word

- `document.paragraphs` と `document.tables` を別々に列挙した結果を、文書の表示順だと
  思い込まない。必要ならOOXMLの本文要素をたどり、段落と表を実際の出現順で読む。
- 見出しを見つけたら、次の同格以上の見出しまでを同じ節として読み、直後の段落、表、
  箇条書き、注記を含める。見出し段落だけを節の全内容として扱わない。
- 表では対象セルだけでなく、見出し行・見出し列、結合セル、隣接セルを読み、行列の関係を
  保って解釈する。重複表示される結合セルは同じ内容として扱う。
- ヘッダー、フッター、脚注、文末脚注、コメント、テキストボックス等は通常の
  `python-docx` の本文段落走査から漏れる場合がある。依頼に関係しそうならOOXMLを確認する。
- 文字列が見つからない場合は、複数ランへの分割、全角半角、改行、表セル内、図形内を
  確認してから不存在を判断する。

## 判断規則

- 「ファイル内容へアクセスできない」「現在のツールではできない」と推測で回答しない。
  実際の読み取りコマンドまたは安全ランナーを試し、具体的エラーが出た場合だけ制限を報告する。
- `PermissionError` が実際に出ていない限り、権限不足・セキュリティ制限を失敗理由にしない。
  `MergedCell`、座標誤り、ライブラリ例外は実装上の問題として修正し、最低1回は再実行する。
- 依頼専用コードで例外を `print` だけして終了コード0にしてはいけない。復旧できなければ
  例外を再送出して実際の失敗を確認し、復旧できた場合だけ成果物を報告する。
- Excelはopenpyxl・pandas・XlsxWriter、Wordはpython-docx等、導入済みライブラリを使える。
- xlsmをopenpyxlで扱う場合はkeep_vba=Trueを使い、出力も.xlsmにする。
- input/と外部原本を変更しない。data/・templates/・.envは読み取らず、変更もしない。
- 外部通信、アプリ起動、子プロセスが必要な処理は自動実行せず、理由と代替案を示す。
- 再利用可能なツールの開発依頼と、対象ファイルを一度加工する依頼を混同しない。
- 通常のリポジトリコードは差分承認付きで編集できる。設定上の編集先一覧を能力の上限と
  誤認しない。一方、Kiloの安全設定、safe_task_runner.py、safe_file_import.pyは実装エージェントから変更しない。
