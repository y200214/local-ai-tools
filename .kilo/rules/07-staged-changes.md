# 複雑な変更の段階実行

複数の実行環境、3ファイル以上、または実装・テスト・デプロイにまたがる変更は、
`stage_guard` が段階管理する。モデルの判断だけで一括実装へ進んではいけない。

1. 読み取り専用で現状と実行環境の境界を確認する。
2. 編集前に `stage_guard(action="plan")` を呼び、3〜10工程を登録する。
3. 各工程には `name`、変更内容 `change`、完了確認 `verify` を必ず含める。
4. 現在工程の変更と確認だけを行う。編集した工程は対象テスト成功まで次へ進めない。
5. 確認結果を `stage_guard(action="advance", evidence="...")` に記録して、1工程ずつ進む。
6. 後の工程で追加編集した場合、それ以前のテスト結果を流用せず再テストする。
7. Open WebUIへの `--apply` は、全工程到達・テスト成功・dry-run成功の後だけ行う。
8. 登録内容一致と業務処理E2E成功を別々に確認する。
9. 最終工程で `stage_guard(action="complete")` を呼んでから完了報告する。
   計画より少ない工程で目的を達した場合は、残り工程が不要になった理由を
   `complete` の `evidence` へ書けば打ち切ってよい。

このガードに止められた場合、迂回用スクリプトや別ツールを作ってはならない。
表示された不足工程または検証を実行してから再試行する。

段階管理が依頼の実態と合っていない(単純な変更まで巻き込まれた、計画が古くなった)
場合は、`stage_guard(action="reset")` で解除してよい。解除したうえで通常どおり進める。
工程計画はファイルへ保存されるため、VS Codeを再起動しても続きから進められる。
