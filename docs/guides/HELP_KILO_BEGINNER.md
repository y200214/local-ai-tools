# 院内ローカルAI はじめてガイド

## このガイドについて

このガイドは、パソコンやAIに詳しくない人向けの説明書です。

このシステムでは、会議の文字起こしから議事録を作ったり、Excelを調べたり、WordやPowerPointを直したりできます。処理は院内のパソコンで行い、外部の生成AIサービスへ業務データを送らない構成です。

難しい名前を最初から覚える必要はありません。まずは「何をしたいか」で使う画面を選んでください。

## 1　最初に見る早見表

| やりたいこと | 使う場所 | 頼み方の例 |
|---|---|---|
| 文字起こしの「えー」「あのー」を消す | Open WebUIの「文章処理」 | ケバ取りして |
| 長い文章を短くする | Open WebUIの「文章処理」 | 800字以内で要約して |
| 文字起こしから議事録を作る | Open WebUIの「文章処理」 | 議事録をWordで作って |
| Excelのシート構成を見る | Open WebUIの「Excel分析」 | シート一覧を見せて |
| Excelから値を探す | Open WebUIの「Excel分析」 | 『合計』を検索して |
| Excelの指定範囲を見る | Open WebUIの「Excel分析」 | 『集計』のA1:F20を見せて |
| Excelの1シートをCSVにする | Open WebUIの「Excel分析」 | 『集計』シートをCSVで出して |
| Excelの全対象シートに所見を書く | Open WebUIの「Excel分析」 | 全対象シートにコメントを作って |
| Excelを詳しく分析・加工する | VS CodeのKilo | inputの○○.xlsxを調べて、結果をoutputへ |
| WordやPowerPointを直す | VS CodeのKilo | ○○を△△に直して、別名保存して |
| 画像やエラー画面を読む | VS CodeのKilo「vision」 | この画面のエラーを説明して |
| システムの故障を調べる | VS CodeのKilo | doctorを実行して。まだ変更しないで |
| システムの機能を変える | VS CodeのKilo「code」 | 変更案と確認方法を先に示して |
| AIの処理手順を管理する | Dify | 管理者がワークフローを確認する |

覚え方は簡単です。

- 普段の文章処理と簡単なExcel操作は、Open WebUIです。
- ファイルの詳しい調査、加工、システム変更は、VS CodeのKiloです。
- Difyは、主に管理者が使います。

## 2　Open WebUIでできること

Open WebUIは、利用者が普段使う「受付画面」です。ブラウザで開き、モデルを選び、日本語で頼みます。

### 2.1　文章処理

モデル一覧から「文章処理」を選びます。文章は貼り付けるか、ファイルを添付します。

できることは次のとおりです。

- ケバ取り：話し言葉の不要なフィラーやつなぎ語を除きます。
- 高速ケバ取り：登録済みルールだけを使い、短時間で処理します。
- 文章整形：意味をなるべく変えず、読みやすくします。
- 要約：長い文章を短くします。文字数を指定できます。
- 議事録：概要、協議内容、決定事項、対応事項に整理します。
- 複数処理：「ケバ取りしてから要約」のように続けて処理します。
- ファイル出力：txt、Markdown、Word、CSV、Excelにできます。
- 続けて修正：同じ会話で「もっと詳しく」「Wordでも出して」と頼めます。

基本操作：

1. Open WebUIを開きます。
2. 「文章処理」を選びます。
3. ファイルを添付するか、文章を貼り付けます。
4. やってほしいことを入力します。
5. 結果を読み、必要ならファイルをダウンロードします。
6. 氏名、日付、金額、件数、期限を原文と照合します。

依頼例：

```text
添付した文字起こしをケバ取りして、800字以内に要約してください。
Wordとテキストの両方で出してください。
```

### 2.2　議事録

文字起こしだけでも議事録を作れます。会議次第と出席者名簿も一緒に添付すると、議題の順番や氏名表記を合わせやすくなります。

```text
文字起こし、会議次第、出席者名簿を使って議事録を作ってください。
数字、金額、期限を省略せず、Wordで出してください。
```

構造化議事録のハイライトには意味があります。

- 緑：文字起こしに根拠があります。
- 黄：会議次第に根拠があります。
- 赤：情報が不明で、人による確認や記入が必要です。

赤は故障ではありません。AIが分からない情報を勝手に作らないための印です。

### 2.3　Excel分析

モデル一覧から「Excel分析」を選び、xlsxまたはxlsmファイルを添付します。ファイルの上限は現在20MBです。一度添付したファイルは、同じ会話なら続けて利用できます。

#### シート一覧

各シートの名前と使用範囲を確認します。

```text
シート一覧を見せて
```

#### 値の検索

全シートから部分一致で値を探します。検索語を『　』で囲むと確実です。表示件数には上限があります。

```text
『再入院率』を検索して
```

結果には、シート名、セル番地、値が表示されます。

#### 範囲表示

指定したシートとセル範囲を表で確認します。

```text
『月次集計』のA1:F20を見せて
```

範囲を指定しないと実行できません。非常に大きな範囲は安全のため拒否されます。

#### CSV出力

指定した1シートをCSVファイルにして添付します。

```text
『月次集計』シートをCSVで出して
```

CSVはExcelの見た目、色、罫線、数式そのものを保存する形式ではありません。表の値を別の処理へ渡したいときに使います。

#### コメント・分析内容の生成

ブック内の表と記入例を基に、表示中のコメント対象シートをすべて処理します。

```text
全対象シートにコメントを作って
```

この処理では、Open WebUIだけで文章を作りません。Windows上のKiloへ安全な経路で処理を渡します。Kiloは次の順に作業します。

1. 表の実データ、単位、比較結果、ブック内の記入例を読みます。
2. ローカルAIでコメント案を作ります。
3. 数値、指標、単位が元データと合うか検証します。
4. 表示中の対象シートをすべて一括処理します。
5. 元ファイルを上書きせず、処理済みExcelを別名保存します。
6. 保存後にもう一度開き、書込み結果を確認します。
7. 複数シートの場合は、コメントと根拠表をまとめた確認用Excelも作ります。
8. 完成したファイルをOpen WebUIへ戻して添付します。

コメント生成には最大30分の待ち時間が設定されています。処理中に同じ依頼を何度も送らないでください。

#### Excel分析で知っておくこと

- シート一覧、検索、範囲表示、CSV出力は、Open WebUI内で直接処理します。文章生成AIは使いません。
- コメント生成だけは、Windows上のKiloとローカルAIを使います。
- 一般的な「自由な質問への回答」をするモデルではありません。用意された操作を日本語のキーワードで確実に選びます。
- グラフや図形の詳しい意味、複雑な集計、複数ブック比較はKiloへ頼む方が適しています。
- 添付した原本は上書きしません。

### 2.4　行数カウントなど

ソースには、文章の空白でない行数と全行数を数える「行数カウント」もあります。Open WebUIへ登録されている場合だけモデル一覧に表示されます。

ソースが存在することと、Open WebUIへ登録済みであることは別です。目的のモデルが見当たらない場合は管理者へ連絡してください。

## 3　VS CodeとKiloでできること

VS Codeは、ファイルやプログラムを扱う作業机です。Kiloは、VS Codeの中で日本語の依頼を受けて調査や作業をするローカルAIです。

### 3.1　基本操作

1. VS Codeで `D:\minutes-pipeline` を開きます。
2. 左側のKiloアイコンを押します。
3. 目的に合うエージェントを選びます。通常はcodeです。
4. 一度に一つの仕事を具体的に頼みます。
5. 変更前の計画や差分を確認します。
6. 内容が正しいときだけ承認します。
7. 完了後、保存先と確認結果を読みます。

内容が分からない承認は、拒否して構いません。拒否しても元のファイルは壊れません。

### 3.2　Kiloの担当

| 担当 | 主な役割 | 注意点 |
|---|---|---|
| code | 通常の開発、Office加工、Excel調査、テスト | 変更前に承認を求める |
| ask | 質問、説明、相談 | ファイル編集やコマンド実行はしない |
| plan | 複雑な仕事の手順整理、読み取り中心の調査 | 原則として実装しない |
| debug | 不具合の原因調査と最小修正 | 一覧に隠れている場合がある |
| docs-writer | Markdown説明書の作成と修正 | コードは変更しない |
| vision | 画像、写真、スクリーンショットの読み取り | ファイルは変更しない |
| data | Jupyter Notebookを使った再実行可能な分析 | JupyterとPythonカーネルが必要 |

### 3.3　Officeファイルを扱うとき

基本は次の3つのフォルダを使います。

```text
input   元ファイルを置く場所。Kiloは上書きしない。
work    作業コピーや依頼専用プログラムを置く場所。
output  完成品を受け取る場所。
```

外部フォルダのファイルを明示した場合は、`work\imports`へ作業コピーを作り、コピーを処理します。外部原本は変更しません。

Kiloはファイルを人と同じまとまりで読むように作られています。Excelならシート全体、検索語の周辺、上下左右、結合セル、罫線、非表示行列、数式などを必要に応じて確認します。Wordなら見出しだけでなく、同じ節の本文、表、注記も確認します。

### 3.4　ExcelをKiloへ頼む例

調査だけ：

```text
input\実績.xlsxから「再入院率」を探し、最新月と前月を比較してください。
根拠のシート名、セル番地、値を示してください。ファイルは変更しないでください。
```

セルの変更：

```text
input\予定表.xlsxの「年間予定」シートB5を「9月12日」に変更してください。
元ファイルは残し、outputへ別名保存し、保存後に値を確認してください。
```

コメント生成：

```text
input\月次評価.xlsxの表示中のコメント対象シートをすべて処理してください。
ブック内の表と記入例を使い、数値を検証し、完成品と確認一覧をoutputへ保存してください。
```

### 3.5　Kilo内部のExcel専用ツール

利用者が名前を覚える必要はありませんが、Kiloが何をしているか確認する目安になります。

- excel_import：外部Excelを安全な作業コピーにします。
- excel_read：シート構造や指定範囲を読みます。
- excel_find：全セルから文字や値を探します。
- excel_write：指定セルを書き換え、別名保存します。
- excel_comment：事実抽出、ローカルAI生成、数値検証、一括書込み、再読込確認を行います。

コメント生成は専用経路です。Kiloは手作業で一部だけ読まず、excel_commentを使って表示中の全対象シートをまとめて処理します。

### 3.6　WordとPowerPoint

```text
input\案内.docxの「令和7年度」を「令和8年度」に置き換えてください。
元ファイルを残し、outputへ別名保存して、置換件数を確認してください。
```

```text
input\説明会.pptxの全スライドから「旧病棟」を「新病棟」に置き換えてください。
完成品をoutputへ保存し、保存後に全文を再確認してください。
```

Kiloは既存ツールで足りない加工にも対応できます。その場合は、依頼専用の小さなPythonをworkへ作り、安全ランナーの中で実行します。書込み先はworkとoutputに制限され、外部通信や別プログラムの起動も制限されます。

### 3.7　画像を読む

visionを選び、PNG、JPEG、GIF、WebPなどの画像を貼り付けます。

```text
このエラー画面に何と書かれているか読み取り、次に確認する場所を説明してください。
変更はしないでください。
```

visionは画像を説明する担当です。修正が必要な場合はcodeへ切り替えます。

### 3.8　システムを調べる・直す

故障時は、最初にdoctorによる読み取り専用の健康診断を行います。

```text
変更はせず、doctorを実行してください。
問題と「対処」を、初心者にも分かる言葉で説明してください。
```

修正を頼むときは、次の順にします。

1. 原因を調べてもらいます。
2. 触るファイル、変更内容、確認方法を出してもらいます。
3. 内容を読んで承認します。
4. 最小限の修正を行います。
5. 自動テストを実行します。
6. 必要な場合だけ本番へ反映します。

複数の環境や3ファイル以上にまたがる変更は、Kiloの工程管理ガードが3～10段階に分けます。現在の工程の確認が成功するまで次へ進めず、テスト前の本番反映も止めます。

## 4　Difyでできること

Difyは、文章をどの順番でAIへ渡し、どの指示で処理し、何を結果として返すかを管理する「AIの作業手順書」です。

主に管理者が行うこと：

- 文章処理ワークフローを見る。
- 入力、AIへの指示、出力のつながりを確認する。
- ワークフローを読み込み、公開する。
- 文章処理がどの段階で失敗したか調べる。

Difyで行わないこと：

- 日常の議事録作成。Open WebUIから頼みます。
- Excelのシート一覧、検索、範囲表示、CSV出力。
- Word、Excel、PowerPointファイルの直接加工。
- 初心者が公開中のワークフローを試しに変更すること。

Difyの変更はOpen WebUIの文章処理へ影響します。変更は管理者がテストと反映手順を確認して行います。

## 5　裏側の仕組み

### 5.1　文章処理の流れ

```text
利用者
  ↓
Open WebUI「文章処理」（受付・操作判定）
  ↓
text-processing-bridge（中継・長文分割・数字の検査・ファイル生成）
  ↓
Dify（AIの作業手順）
  ↓
OllamaのローカルAI（文章処理）
  ↓
bridgeが結果を確認し、Wordなどを生成
  ↓
Open WebUIへ結果を返す
```

### 5.2　Excel分析の流れ

シート一覧、検索、範囲表示、CSV出力：

```text
利用者
  ↓
Open WebUI「Excel分析」
  ↓
Open WebUIコンテナ内のExcel処理
  ↓
画面表示またはCSV添付
```

コメント生成：

```text
利用者
  ↓
Open WebUI「Excel分析」
  ↓ HTTP（8010番）
local_tool_bridge（Windows上の受付）
  ↓
Kilo CLIのexcel_comment
  ↓
事実抽出 → ローカルAI生成 → 数値検証 → 全対象シートへ書込み
  ↓
処理済みExcelと確認一覧をOpen WebUIへ返す
```

この分け方により、Excelコメントの処理をOpen WebUI用に重複して作らず、Kiloで検証済みの道具を共通利用します。

### 5.3　それぞれの役割

| 名前 | やさしい説明 |
|---|---|
| Open WebUI | 利用者が普段使う受付画面 |
| VS Code | ファイルやプログラムを扱う作業机 |
| Kilo | VS Code内で調査、加工、開発をするローカルAI |
| Dify | AIへ仕事を渡す順番を管理する作業手順書 |
| Ollama | このパソコンでAIモデルを動かすエンジン |
| text-processing-bridge | 文章処理の中継、安全確認、ファイル生成をする係 |
| local_tool_bridge | Open WebUIからWindows上のKiloツールへ渡す受付 |
| Docker | 各サービスを分かれた箱で動かす仕組み |
| Pipe | モデルとして選ぶと、決められた処理を確実に行う機能 |
| Tool | 通常のAI会話中に、AIが必要と判断して使う道具 |

## 6　安全のための決まり

### 6.1　触らない場所

- data：実在の会議データや個人情報があります。
- templates：正式な文書テンプレートがあります。
- .env：APIキーなどの秘密情報があります。

Kiloには、これらを読んだり変更したりできない安全柵があります。内容をチャットへ貼り付けることもしないでください。

### 6.2　元ファイルを守る

- inputと外部原本は上書きしません。
- 作業途中はworkを使います。
- 完成品はoutputまたはOpen WebUIの添付ファイルとして受け取ります。
- xlsmはマクロを保つ方法で処理し、出力もxlsmにします。

### 6.3　承認画面を見る

- 追加される内容と削除される内容を確認します。
- 依頼と関係のないファイルがあれば拒否します。
- data、templates、.env、Kiloの安全設定を触ろうとしていれば拒否します。
- 分からない場合は拒否し、管理者へ相談します。

大量削除、git push、危険なDocker操作などはKiloから実行できないよう制限されています。

### 6.4　AIの結果を確認する

AIは読み違えることがあります。次の項目は必ず原文や表と照合してください。

- 人名と部署名
- 日付と時刻
- 金額、件数、割合、単位
- 締切と担当者
- 決定事項と未決事項
- Excelコメントが参照した数値

## 7　困ったとき

### 7.1　利用者が試すこと

1. 正しいモデルを選んでいるか確認します。
2. 対応するファイル形式か確認します。
3. 一度に一つの依頼へ分けます。
4. 同じ会話で混乱したら、新しい会話を作ります。
5. Kiloならdoctorを実行します。
6. テスト失敗や原因不明のエラーは、そのまま管理者へ伝えます。

### 7.2　症状別の確認

| 症状 | 確認すること |
|---|---|
| Open WebUIが開かない | サービスが起動しているか管理者へ確認 |
| 目的のモデルがない | Open WebUIへ登録済みか管理者へ確認 |
| 文章処理だけ失敗する | text-processing-bridge、Dify、Ollamaをdoctorで確認 |
| Excelの一覧や検索が失敗する | xlsxまたはxlsmか、20MB以下か確認 |
| Excelコメントだけ失敗する | local_tool_bridgeとKilo CLIの起動状態を管理者が確認 |
| 検索結果が多すぎる | 検索語を長く、具体的にする |
| 範囲表示を拒否された | A1:F20のように小さく分ける |
| CSVで書式が消えた | CSVは値中心の形式。書式を保つならxlsxを使う |
| Kiloが止まった | 承認待ち、工程確認待ち、テスト失敗を確認 |
| Kiloが違う作業を始めた | 停止し、新しい会話で一つだけ頼む |

## 9　管理者向けの入口

日常利用者は実行しません。

- 健康診断：`python tools\doctor.py`
- ローカルツール受付：`text-processing-bridge\.venv\Scripts\python.exe tools\start_local_tool_bridge.py`
- 文章処理のテスト：`cd text-processing-bridge; .\.venv\Scripts\python.exe -m pytest -q`
- ブリッジ反映：`docker compose -f text-processing-bridge/docker-compose.yml up -d --build`
- Open WebUI登録前確認：`python tools\open_webui_deploy.py tools\対象.py`
- Open WebUIへの反映：確認コマンドへ `--apply` を追加します。

Open WebUIの登録成功と、実際の業務処理が最後まで成功することは別です。登録後に架空データで実ファイル処理と成果物の再添付まで確認します。

## 11　用語集

| 言葉 | 意味 |
|---|---|
| xlsx | 一般的なExcelファイル |
| xlsm | マクロを含められるExcelファイル |
| CSV | 表の値を文字で保存する形式。Excelの色や罫線は保たない |
| セル番地 | A1、B5のようなExcelのマスの住所 |
| ローカルAI | 外部サービスではなく、このパソコン内で動くAI |
| エージェント | Kiloの担当分け。code、visionなど |
| 差分 | 変更前と変更後の違い |
| テスト | 変更後も機能が壊れていないか確かめる自動検査 |
| 再読込検証 | 保存したファイルをもう一度開いて結果を確かめること |
| API | 別のプログラム同士が仕事を受け渡す入口 |
| ポート | プログラムの受付番号。local_tool_bridgeは8010番 |
