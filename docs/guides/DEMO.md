## 本番の流れ

### 1. つかみ(2分) — 「全部この1台の中」
- タスクバーのネットアイコンを見せて「これ、インターネット無しで全部動きます」
- 「会議の音声も文字も、**院外のサーバーには一切送っていません**。ChatGPTと違ってデータが外に出ない」← 病院で一番刺さる点

### 2. 本業デモ(5分) — 議事録ができるところ
- Open WebUI(いつもの画面)でデモ用文章を貼り、「ケバ取りして」→ フィラーが消える
- 「議事録にして」→ 整形された議事録が出る
- 一言: 「ここまでは普段お見せしている機能です。今日は**この道具を直す作業もAIがやる**のをお見せします」

### 3. 開発デモ(5分) — 先生の一言でシステムが変わる ★メイン
1. 先生に聞く: 「会議でよく出る口癖、何かありますか?」(出なければ「なんと言いますか」を使う)
2. VSCodeのRooに、その場で日本語入力:
   > config/kebatori.yaml のフィラー定義に「(先生の挙げた口癖)」を追加して、tests/test_kebatori.py にそれが除去されるテストを足して、docker compose -f text-processing-bridge/docker-compose.yml run --rm bridge python -m pytest -q でテストが全部通ることを確認して。最後に docker compose -f text-processing-bridge/docker-compose.yml restart bridge で反映して
3. 待ち時間(1〜2分)のトーク: 「いまAIがルールファイルを書き換えて、壊れていないかの自動検査を57項目実行しています」
4. テスト緑が出たら、**さっきのtext-toolsページで同じ文章をもう一回処理** → 先生の口癖が消えている ← 拍手ポイント
   - ※ kebatori.yaml は設定マウントなので反映は restart のみでOK(ビルド不要)

### 4. 締め(2分) — 信頼性の担保
- `git log` を見せる: 「AIがやった変更は全部記録されていて、1秒で元に戻せます」

## 失敗時の保険

| 起きたこと | 対処 |
|---|---|
| Rooが変な方向に走り出した | 止めて「もう一度、〇〇だけやって」と言い直す(「AIも聞き返しが要るんです」と笑いに変える) |
| それでもダメ | リハーサルで撮っておいたスクリーンショットで説明に切り替え |
| 変更が中途半端に残った | `git -C D:\minutes-pipeline checkout -- .` で即時全戻し(これ自体が「安全装置」のデモになる) |
| Open WebUIが不調 | text-toolsページ(`localhost:8008/text-tools`)だけで完結させる |

## gpt-oss回答サンプル(締めで見せる用・事前生成済み)

質問: 「agenda.py の責務を3行で要約し、最も改善価値が高いリファクタ候補を1つ提案して」

> **モジュールの責務(3行)**
> 1. 会議次第テキストを正規表現で解析し、トピック・項目・担当者・資料番号といった構造化情報へ変換する
> 2. 全角→半角・丸数字などの文字列正規化を行い、照合キーを一意に生成できるよう整形する
> 3. 取得したデータを Agenda / AgendaTopic / AgendaItem の dataclass に格納し、上位ロジックが利用できる形で提供する
>
> **最も改善価値が高いリファクタ候補**: parse_agenda を「AgendaParser」クラスに分割し、処理を小さなメソッドへ委譲する(理由: 多種多様な判定が混在して読みにくい / 状態をインスタンス属性で管理できる / 単体テストが容易になり、将来PDF・HTML等の入力形式拡張時も入口を変えずに済む)
